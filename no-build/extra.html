1
Rawdogging node_modules/ imports

```diff - import { marked } from 'marked'; + import { marked } from '/node_modules/marked/lib/marked.esm.js'; ```

The Good It works! 🎉

…for this particular case

The Bad Requires deploying node_modules/

Wasteful and insecure. Most hosts do not even deploy `node_modules/` by default. Now you need additional ad hoc tooling to make this work in prod.

The Bad We just lost the abstraction of specifiers

Have you wondered why we use specifiers and not URLs? Specifiers are an _abstraction_ over URLs. They decouple the actual file structure from the dependency.

The Ugly Breaks with transitive dependencies

```js import {html, css, LitElement} from '/node_modules/lit/index.js'; ``` ```error { .delayed } Uncaught (in promise) TypeError: Failed to resolve module specifier "@lit/reactive-element". Relative references must start with either "/", "./", or "../". ```
But the real dealbreaker is that even if you stomach all other warts, this only works for dependencies that don’t use dependencies. Once a dependency has its own dependencies, this approach breaks down completely.

2
Import from CDNs

```js import {html, css, LitElement} from 'https://esm.sh/lit'; ``` - Transitive dependencies work - Specifiers, not paths (mostly) { .check-list .green .text .delayed-children }

A point of failure you don’t control

It is always a bad idea to introduce a dependency on a whole other domain you do not control, and an even worse one when linking to executable code. Any third-party domain is an unnecessary additional point of failure you do not control. I still remember scrambling to change JSDelivr URLs to Unpkg during an outage right before one of my talks, or having to hunt down all my repos that used RawGit URLs when it sunset, including many libraries. Wanted to code on a flight? Good luck. Needed to show a live demo during a talk, over clogged conference wifi? Maybe sacrifice a goat to the gods first. More complexity: - How to avoid CDN roundtrips for local dev? - Proxies for APIs that require COEP/single-origin isolation.
## Inconsistency
Because everything is URLs, nothing prevents the same module from being referenced in multiple ways (different versions, from different CDNs, etc), leading to potential inconsistencies and even bugs.

The Bad What about local packages?

If a CDN is both your package manager and your source of executable code, how do you modularize _your own_ code?

The Ugly Security implications

Unless you link to a specific version, down to the patch number and/or use SRI, the resource could turn malicious overnight under your nose if the package is compromised. And even if you link to a specific version, there is always the risk that the CDN itself could get compromised. Who remembers polyfill.io?
